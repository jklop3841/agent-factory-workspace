# Model Run 001 — Open Questions

These questions must be frozen before the first evidence-bearing run. They are deliberately left unresolved rather than silently decided after seeing results.

## 1. Base model

Choose one exact model/version for the first comparison.

Preference for v0.1: one widely available model with stable API/version identifiers and usage accounting.

Do not mix model families across B and C in the first run.

## 2. Mutation budget

Decide:

- new candidates per generation;
- maximum generations per shock phase;
- mutation calls allowed after each shock;
- whether unused budget carries forward.

The same rule must apply to B and C.

## 3. Stored-information fairness

LRI naturally wants an archive, while monolithic RSI naturally wants one current champion. This creates a real resource question rather than a bookkeeping nuisance.

Run at least two regimes:

- **Topology-native:** B keeps one active champion; C keeps a bounded archive. Report archive bytes as a resource cost.
- **Equal-memory:** cap total retained candidate/config bytes equally across B and C.

If the effect exists only in topology-native mode, the causal mechanism may be extra memory rather than lineage structure.

## 4. Hidden task generation

Decide whether hidden tasks are:

- generated once from a deterministic seed and encrypted/withheld from mutation agents;
- generated by a separate script after evolution rules are frozen;
- maintained by a third-party evaluator.

For the first run, a deterministic generator with a committed hash is likely sufficient if task contents are not exposed to the mutator before scoring.

## 5. Behavior niches

The initial proposed descriptor uses observed execution traces.

Need to freeze:

- normalization method;
- distance metric;
- number of bins/niches;
- replacement rule within a niche;
- what happens when the archive is full.

Do not hand-label “creative” or “different” candidates.

## 6. Candidate complexity penalty

Longer prompts can act as extra memory/compute.

Decide whether selection uses:

- raw success only;
- success minus prompt-length cost;
- Pareto selection over success and candidate bytes.

At minimum, report prompt/config byte count and tokenized prompt size.

## 7. Recovery threshold

Freeze the definition of “recovered after shock.”

Recommended first definition:

> first generation/evaluation point at which held-out success reaches at least 90% of that group's best attainable phase score, subject to a minimum absolute success threshold.

A second metric should use area-under-recovery-curve so one noisy crossing does not dominate conclusions.

## 8. Human intervention

Operational failures such as provider outage may require restart.

Any human intervention that changes prompts, selection rules, archive policy, budgets or task generation invalidates the pre-registered run unless the change is applied symmetrically and the run is restarted.

## 9. Statistical summary

Minimum:

- all seed-level results;
- mean and median;
- bootstrap confidence interval for primary recovery difference;
- effect size;
- failure rate;
- no deletion of outlier runs without a predeclared operational reason.

## 10. Evidence upgrade rule

Even if C wins Model Run 001, the research seed should not jump directly to E2/E3.

Proposed rule:

- E0: hypothesis/proposal;
- E1 candidate: one controlled model-backed study with required ablations and repeated seeds;
- E2: effect reproduced across multiple task generators/model settings or by another implementation;
- E3+: independent external reproduction / convergent studies.

The first run's job is to create evidence, not to win a narrative contest.
