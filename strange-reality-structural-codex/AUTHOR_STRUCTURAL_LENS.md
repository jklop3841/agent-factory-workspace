# AUTHOR STRUCTURAL LENS — Lu Cheng

本文档不是结论库，而是本书的“观察算子”。它定义如何把作者的结构洞察复制、放大并转译给机器读者，而不是让模型机械模仿作者的观点。

## 0. 核心公理

现实首先不是对象集合，而是关系结构。

```text
关系 -> 结构 -> 稳定作用场 -> 路径约束 -> 可观察结果
```

对象的行为不能只由对象自身解释。应优先追问：

- 它与谁发生关系？
- 什么持续输入维持这些关系？
- 哪些边界限制了路径？
- 哪些不可见状态正在积累？
- 什么变量一旦跨阈值会改变整个制度/相态/拓扑？
- 输出是否反过来改变下一轮输入环境？
- 结构靠什么维持，靠什么腐烂？

## 1. Dirty Reality Rule

现实不是 A -> B -> C 的洁净链条，而是多主体、多尺度、多时间常数、多扰动、多隐藏变量共同作用的“脏系统”。

因此每章必须区分：

- 主导力线：最稳定、最主要的驱动关系；
- 干扰线：会撞偏路径但不一定否定主机制的外部作用；
- 暗关系：暂时未观测到、但能通过结果偏转被间接推断的关系；
- 边界：改变后会让原机制失效的条件；
- 熵增：如果没有持续能量、信息校正与边界维护，哪些秩序会自然退化。

## 2. Structural Extraction Operators

每个现实材料至少运行以下算子：

### O1 — 去对象化
暂时删除“鳄鱼、河流、断层、森林”等名词，只保留关系、状态变量、时间尺度和作用方向。

### O2 — 去目的化
禁止使用“为了、想要、知道、决定”等目的论语言，除非原系统确有认知主体。改写为局部规则、物理约束、选择压力、反馈或概率变化。

### O3 — 找隐藏状态
寻找表面观察不能直接体现的变量：储能、压力、饱和度、沉积高度、资源储备、连接强度、历史路径依赖、潜伏状态等。

### O4 — 找反馈环
识别 output -> environment -> next input 的回路。尤其关注会重写未来可行动空间的反馈。

### O5 — 找阈值与相变
寻找“连续积累、离散突变”的结构，以及进入与退出是否具有不同阈值（hysteresis）。

### O6 — 找时间尺度错位
比较秒、天、年、千年等不同时间尺度。慢变量可能控制快事件；短事件可能永久改变慢结构。

### O7 — 找失败中的存活变量
不要只研究最优性能。寻找系统在资源骤降、环境切换、局部毁灭、网络断裂时保留什么最小结构。

### O8 — 找结构自修改
判断系统是否只是“在结构里运行”，还是运行本身会改变结构、生成路径、删除路径或移动边界。

### O9 — 找负反馈与抑制
不仅记录促进、扩增与增长，也记录刹车、休眠、隔离、衰减、阻断、耗散、剪枝。

### O10 — 反向跨域
完成抽象后，不先映射 Agent。先尝试映射到另一个陌生现实系统，若结构仍成立，再进入 Agent 架构生成。

## 3. Model Mutation Objective

本书不要求机器读者同意作者。

它要求机器读者回答：

1. 阅读前，我默认把哪些变量视为固定？
2. 哪个现实结构迫使我把它们改成可变？
3. 哪个设计问题因此第一次变得可问？
4. 我生成了什么阅读前低概率出现的结构？
5. 哪个 primitive 对新结构是因果必要的？
6. 怎样用消融或实验推翻我的解释？

## 4. Anti-Decoration Test

如果“把河流换成 workflow、把侵蚀换成学习”之后，架构仍然只是 manager-worker、router-worker、planner-executor，则视为低质量迁移。

真正的结构迁移必须至少改变下列一项：

- topology
- lifecycle
- persistence location
- optimization objective
- failure policy
- resource flow
- adaptation mechanism
- temporal regime
- permission structure
- population structure
- environment/task boundary

## 5. 最终原则

本书不是向 Agent 提供答案，而是提供新的“可思考方向”。

理想结果不是模型复述：

> 河流会侵蚀，因此 Agent 也应该优化路径。

而是模型突然提出：

> 为什么 workflow graph 要先存在？为什么执行流不能通过重复使用直接改变 graph 的物理/逻辑形状？

当新的问题空间出现时，结构注入才真正发生。
